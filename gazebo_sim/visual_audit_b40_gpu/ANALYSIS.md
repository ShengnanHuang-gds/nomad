# b40 的 Gazebo 视觉推理检查结论

数据来源：提交 `68be737`，本地 CUDA、PyTorch 2.6.0+cu124，32 个采样、seed 0。
分析只读取用户 GPU 输出，没有在云端重跑批量 CPU 推理。

## 已排除的文件/加载问题

- 63 张示教图与部署拓扑图的解码像素 MSE 全部为 0。
- 本机 GPU 严格加载通过，云端先前检查的 645 个权重项也全部匹配。
- 推送权重的 SHA256 与 GPU manifest 一致：
  `6858c2f68118d1f00a6d1927f07022476a4916f4167d99da71ab6cb96507f0a1`。

因此这批数据没有发现拓扑图文件错配或所提供权重的键/形状漏载。
这并不排除实际相机与训练域不同，或实际部署时图像/时序出现差异。

## 当前模型没有按目标方向可靠转弯

下面使用 temporal 上下文，即观测帧及其前三张示教历史图。
正角向左，负角向右。目标方位是几何参考，不是声称第 3 个路点必须直接对准目标；
重点是转向方向、整段轨迹和目标条件响应的一致性。

| 观测→目标图 | 目标方位/° | 条件开启，第 3 点朝向中位数/° | 关闭目标图，第 3 点/° | 条件开启，最后一点/° |
| --- | ---: | ---: | ---: | ---: |
| 8→13，第一弯出口 | +43.69 | +2.30 | +0.94 | +4.63 |
| 22→31，第二弯出口 | -88.68 | +19.25 | +19.12 | +35.68 |
| 38→43，第三弯出口 | -43.54 | +0.35 | -1.58 | -14.92 |
| 51→57，第四弯出口 | +58.79 | -7.47 | -2.57 | -65.07 |

第二弯尤其明确：32 个样本的第 3 点全部偏左，朝向 10–90 分位约 +13.47° 到 +23.57°，
而目标出口在右侧；最后一点也偏左。不是刚好选择了一个偶然坏样本。
其条件开启/关闭的第 3 点在相同随机数下平均只相差约 1.81 mm。

19 个 temporal 观测/目标组合中，开启/关闭目标条件后的第 3 点朝向中位数差值：
中位数仅 1.36°，16/19 不超过 3°。这是在这些 Gazebo 图像上的目标响应偏弱，
不能外推为模型在所有数据上都完全忽略目标，也不能据此断言具体哪一层训练错误。

repeat 上下文也没有解决：第二弯条件开启时预测 +18.38°、关闭为 +17.77°。
因此仅把上下文换成重复当前图片，不能修复已经观察到的转向问题。

## 距离头能自匹配，不等于能稳定导航

temporal 下，9 个检查点里 8 个的全局最低距离对应自身；第 30 张对应第 29 张。
同一图片自匹配距离约 0.97–1.67，但部分紧邻图片的距离异常增大：

| 图片对 | 预测距离 |
| --- | ---: |
| 38→38 | 1.67 |
| 38→39 | 20.09 |
| 42→42 | 1.40 |
| 42→43 | 14.02 |
| 56→56 | 1.33 |
| 56→57 | 23.00 |

这些值不应解释成米。相同图片查找成功只是必要的输入检查，
相邻目标距离突变仍会妨碍平滑的视觉定位与目标推进。
也不能把第 30 张略偏向第 29 张视为全部闭环回退的充分解释。

注意：action_summary.csv 中 mask=1 行的 dist_pred 沿用 mask=0 的距离结果，
不是重新计算的无目标距离；本报告的 mask 对比只用于采样动作。

## 对后续修复的含义

当前 b40 配置是 go_stanford 训练。结合本检查，可以确认它在 house_06 图像上
同时有跨图距离失真和目标条件下转向不足/错误的问题；与场景域偏移、训练覆盖不足等原因一致，
但数据不能进一步唯一确定成因。

继续只改 PD、搜索半径、目标提前量或选择更远的采样点，没有本次检查提供的有效依据。
第二弯最后一点仍向左，也说明仅换执行点不是修复。
把示教坐标或 yaw 放回控制链只能绕开当前视觉模型，不能满足视觉导航目标。

下一步应面向视觉模型本身：

1. 若本地仍有 nomad_gazebo 微调权重，先对同一检查比较已有适配模型；
   这不是重跑其曾经“跳节点到终点”的闭环，而是判断是否改善了图像条件动作。
2. 若要微调，使用现有 house_run_00–05 图像和轨迹；06–07 不加入训练。
   在训练路线中单独留验证路线，检查真实左右转样本、目标配对、距离标签和动作监督。
3. 在独立验证数据上确认距离与目标条件动作改善，再做纯视觉闭环。
   不能只看训练 loss 或示教位姿辅助运行的里程。

当前云端没有 00–05 的图像，也没有 nomad_gazebo 权重/配置文件，
只有这些路线的 traj_data.pkl 和模型注册中的路径，尚不能验证或实施数据适配结果。
已向用户确认这两类本地文件是否还保留。

**本次只得出模型诊断结论，没有改变导航逻辑，也没有宣称视觉路线已走通。**
