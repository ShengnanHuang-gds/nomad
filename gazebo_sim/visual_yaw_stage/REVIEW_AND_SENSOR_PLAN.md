## 可以确认的结果

训练 loss 从首轮约 0.484 降到末轮约 0.039，05 的角度 MAE 却从 46.24° 升到 57.26°，
p90 从 92.08° 升到 127.57°。这是训练拟合未转化成验证改善的证据。
不能只凭 loss 下降宣称学会朝向，也不能用加 epoch 作为当前有依据的修复。

6756 个训练图像对来自 00–04 的 216 张图像，并不是 6756 个独立场景。
1138 个验证对也只来自 05 的 38 张图像。
本次验证覆盖帧差 ±20，包含移动较远、转弯后视野重合很少的图像，
不应默认每个静态图像对都足以唯一推断相对朝向。
我此前直接用这些对训练通用朝向头，尚未先验证图像的可观测范围与姿态/时间对应关系，
这部分设计需要重新审查，不能再让用户盲目重复同类训练。

## 已做的原图核对

- 全部 254 张训练/验证图片的解码像素哈希互不相同，没有发现完全相同的重复帧。
- 检查相邻帧中 position 变化小于 0.01 m、odom yaw 变化超过 10° 的 21 对。
- 使用 OpenCV 5.0.0、SIFT 最多 1000 个特征、ratio 0.7、双向匹配互检，
  19/21 对少于 8 个互相匹配点。详情见 `image_pair_geometry.csv`。

这只是特征重合诊断，不能从“匹配点少”推导出模型必然无法识别，
也不能直接认定相机或标签错误。纹理弱、视野不重合、重复墙面都可能影响匹配。

另有两组值得核对：03 的 20→21，odom yaw 变化 +58.6°，
相似变换拟合为约 +3.9° 图像平面旋转、31 个内点；03 的 29→30，
odom yaw 变化 -43.4°，图像平面旋转约 +1.0°、25 个内点。
**图像平面旋转不是底盘 yaw**，未标定鱼眼和相机外参时不能把两个角直接相减判断标签错了。
重复场景也可能产生相似外观。需要实际相机模型、真实 Gazebo 姿态和时间戳来区分。

## 尚缺的证据

1. 实际 burger_cam 的 SDF/URDF/Xacro、传感器 pose、镜头类型/映射与 FOV。
2. CameraInfo 和 base→camera 的实际 TF；图像话题是否只有正确的模拟相机发布。
3. `/odom` 的实际来源：轮式积分还是 Gazebo 真实位姿，以及真实机体 roll/pitch/yaw。
4. 同一时段的 image、odom、Gazebo pose 时间戳。旧 PKL 只有 position/yaw，
   无法事后证明图像和位姿严格同步；记录器使用各自最近一次回调值，不等于按图像时间对齐。

可能是小数据过拟合、图像对缺少共同视野、相机方向/投影差异、
轮式里程计与真实运动偏差或消息同步问题；当前记录不足以唯一确定。
下一步先核验这条链路，而不是再换一个网络或扩大训练轮数。
