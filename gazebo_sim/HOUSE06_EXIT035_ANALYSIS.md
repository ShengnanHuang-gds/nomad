## tick 超时也不合适

导航记录持续 148.55 秒主机时间，odom 消息时间只推进 16.30 秒，
仿真实时率约 0.1097。最高线速度 0.2 m/s，走完 4.56 m 的平移理论下限
就是 22.8 秒仿真时间，还没包含原地转弯。即使控制完全正确，600 tick 的预算也不足。

脚本现默认 `MAX_TICKS=0`、`MAX_SIM_SECONDS=60`，按 odom 消息时间计算导航时间。
保留 `MAX_WALL_SECONDS=900`，防止仿真停住无限等待。
显式设置 `MAX_TICKS=600` 仍会启用旧的 tick 上限；新复验请不要沿用该覆盖。

## 新增 `TEACH_ROUTE=1` 整段位姿辅助

这是一个独立、显式开启的诊断模式，不是 NoMaD 纯视觉导航：

1. 用现有示教位置顺序跟随 5 段平移路径，前视距离 0.25 m。
2. 到达每段末端 0.04 m 内后，完成对应原地转弯，再进入下一段；不依赖视觉节点触发转弯。
3. 不允许靠跳到最终位置或视觉节点到达终点而跳过中间路段。
4. 所有路段依次完成、到达真实终点 0.04 m 内，才报告本模式的成功。
5. 脚本为该模式开启碰撞代理停车；阈值沿用现有 0.15 m，不掩盖碰撞继续开。

模型仍运行并记录输出作为对照，但运动路点由示教位姿辅助决定。
视觉图像检索窗口围绕几何前视目标，CSV 标记 `localization_window_source=teacher_pose`；
此模式下 dist、closest_node 不再是独立的纯视觉定位性能指标。
CSV 的 `control_source=teach_route_drive/spin/done`，以及 `route_leg/route_goal`、
`endpoint_error_m/sim_elapsed_s` 可直接查看辅助进度。
JSON 记录 `teach_route=true` 与 `success_criterion=ordered_teacher_legs_and_endpoint_0.04m`，
保证和旧的“节点到终点”结果区分。

## 原 WSL 运行命令

先拉取最新 main；T1 启动新的仿真实例：

```bash
bash gazebo_sim/launch_tb3_house_at_run.sh house_run_06
```

T2 在仓库目录运行：

```bash
TEACH_ROUTE=1 MAX_TICKS=0 MAX_SIM_SECONDS=60 MAX_WALL_SECONDS=900 \
EPISODE_OUT="$PWD/gazebo_sim/episodes_eval_gpu/house_06_nomad_b40_teach_route.json" \
bash gazebo_sim/run_holdout_06_b40.sh
```

不重录示教，不覆盖 exit035 原始记录。脚本仍 source `nomad_wsl_env.sh` 并使用 `$NOMAD_PY`。
这次可能需要数分钟主机时间；60 秒是仿真时间上限，不是主机等待时间。
运行结束请保留新的 JSON、ticks.csv 和 control.csv。

若此模式也失败，优先查看 route_leg、真实位置与碰撞代理，定位路线/控制/仿真问题；
若此模式成功，只能说明示教路线和控制链能够走通，之后仍需单独解决视觉目标定位和模型偏航。
