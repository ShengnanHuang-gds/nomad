# 按仿真时间对齐的 burger_cam 采集

来源脚本是 main 上的 `f1ad416`：`gazebo_sim/capture_sensor_alignment.py`。采集只订阅。转动用单独的 `align_spin_once.py`，线速度为 0。没有传送，没有示教姿态，没有跑 NoMaD 或 PD。

模型 ID 来自 `gz model -m burger_cam -p`：世界 `default`，实体 `burger_cam`，ID **271**。当时位姿约 `(-2.200, 1.200, 0.010)` m，RPY 约 0。这是本次 house 启动的出生点，也是 `house_run_06` 的起点；禁止传送，所以没有挪到 05/06/07 以外的另一处。转动前扫描最近距离分别约 0.854 m 和 0.874 m。

生效镜头文件 SHA256：`394a0403aecd8cb0e251dff31eb455c527145d745b1ef05e36096379de8b2493`（`model.sdf`）。图像只有 `ros_gz_image` 在发布，`/odom` 只有 `ros_gz_bridge` 在发布。发速度前 `/cmd_vel` 的发布者数量是 0，订阅者是 `ros_gz_bridge`。

每次采集 4.0 s 仿真时间，主机约 31 s。零时间戳都是 0，`samples.json` 里 `errors` 为空。每窗 122 张图、122 个互不相同的文件名和图像戳；其中 120 张能在 50 ms 内同时套到模型姿态和 odom。最大单侧间隔 19 ms。另外 2 张没有双侧支撑，没有拿别的窗口补。

静止段按模型 yaw 变化小于 0.35°、并且持续时间至少 0.4 s 来切。比较的是转前最后一张和转后第一张对齐图。

| 窗口 | 转前 / 转动 / 转后 | 模型 yaw 增量 | odom yaw 增量 | 两路差 | 图像中位位移 |
| --- | ---: | ---: | ---: | ---: | --- |
| 静止 | 120 / 0 / 0 | +0.000° | 0.000° | 0.000° | 76 对，+0.01 px，+0.01 px |
| 左转 +0.12 rad/s | 21 / 41 / 58 | +9.522° | +9.529° | -0.008° | 32 对，+15.69 px，+0.12 px |
| 右转 -0.12 rad/s | 20 / 41 / 59 | -9.520° | -9.529° | +0.010° | 36 对，-15.84 px，-0.06 px |

左转时场景中位位移向右，右转向左。这只说明这次小角度、还有共同视野时方向一致。没有用 CameraInfo 的 K/D，也没有把像素位移换算成机体 yaw。

模型水平位移大约 1–2 mm。odom 水平位移是数值零附近。odom 的 roll、pitch 仍是 0。模型 pitch 在静止段大约 -0.21° 到 -0.26°，左转两端大约 -0.48° 到 -0.62°，右转两端大约 -0.63° 到 -0.60°。roll 接近 0。

代表帧在 `representatives.tar.gz`，路径和戳记在 `summary.json`。三份 `samples.json` 保留全部消息元数据。匹配点在各窗口的 `sift_matches.json`。完整 PNG 留在本机各窗口的 `images/`，没有全部推上去。

这次只核对同步和大约 10° 的方向。不能说明 05 上朝向头失败的原因，也不能当作闭环结果。
