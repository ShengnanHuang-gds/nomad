# 当前目标：NoMaD 视觉导航走通 house_06

用户已明确纠正目标：通过相机图像与拓扑图进行视觉定位，由模型输出运动路点。
此前 teacher-route 结果属于使用示教坐标/朝向的控制诊断，不能算视觉导航改善或成功。
它没有解决模型在转弯处不给足转向、视觉匹配落后而选择到车后方目标图的问题。

## 主入口现在只运行视觉模式

`run_holdout_06_b40.sh` 固定传入 `--visual-only`，忽略残留的 `TEACH_ROUTE`、
`TEACH_YAW_SPIN` 环境变量。命令行也禁止将 `--visual-only` 与任意示教辅助开关组合。
导航中的示教路点覆盖函数直接返回空，不读取位置或 yaw 来生成路点。

相机和拓扑图片决定定位/子目标，发布模型选定的 sample 0、waypoint 2 路点，
保留原有尺度转换、PD 控制、半径 4、距离阈值 5、lead 1。
激光只用于原有近障停车；odom 用于日志、时间预算及起点核验。
初始 spawn/reset 是实验初始化，不在导航中按示教朝向转弯。

原有辅助模块暂留作历史复现工具，主入口不会启用它们。
旧文档中 `TEACH_ROUTE=1 ... run_holdout_06_b40.sh` 的指令已不再启动示教模式。

## 这次增加的数据用于检查模型本身

默认输出名改为 `house_06_nomad_b40_visual.json`，还会生成：

- `.ticks.csv`、`.control.csv`：已有的视觉定位、路点、命令和执行日志。
- `.ticks.runtime.json`：本机实际使用的模型配置、权重路径/文件大小、拓扑图文件清单、预处理方式与模式。
- `.vision/`：视觉节点或距离是否达标发生变化时，以及每 20 tick 保存一次无损 RGB 上下文图片、
  目标图片及 `predictions.jsonl`。记录相机消息时间、完整距离窗口、全部采样轨迹、采样/路点索引和尺度转换。

这些 RGB 是实际传入预处理的图片，不是事后用示教图代替。
它们用于检查图像/时序输入、定位结果、目标条件与轨迹采样，而非继续添加位姿控制。
`.vision` 的 PNG 可能被仓库全局规则忽略；如需推送数据，可将整个目录压缩为 tar.gz 后提交，
无需修改全局图片忽略规则。

## 运行方式

如果需要采集当前纯视觉运行的输入输出，先拉取代码并新启动仿真。
T1 使用原来的 `launch_tb3_house_at_run.sh house_run_06`，T2 直接：

```bash
bash gazebo_sim/run_holdout_06_b40.sh
```

不需要设置任何 TEACH 环境变量。
这不是一个已经修好模型转弯的版本，不预期仅靠关闭辅助就会走通。
已有“b40 对第 12 帧只给小角度转向”的结论仍然有效，不再重复搜索半径、lead 或执行点的盲试。

## 尚未解决与实际限制

当前云端没有本机 `nomad_b40` 权重，也缺 ROS/Gazebo 运行环境。
版本库的 `deployment/config/models.yaml` 没有本地注册的 `nomad_b40` 条目，
因此仅凭库里的默认配置无法确认 WSL 实际加载的是哪一组配置和权重。
新的 runtime 文件可以补足这一点。

没有相同模型权重或实际视觉推理输入，不能确定是加载/配置不一致、图像域差异、
上下文时序、视觉目标选择还是模型能力本身导致失败，更不能保证修正其中一个就能走通。
下一步优先复现实际模型的视觉推理，检查定位和转弯输出，而不是按坐标替模型驾驶。

27 项离线检查通过，其中新增的 3 项验证视觉模式禁止示教开关、
覆盖函数不读取位姿、以及导出图片像素与采样元数据完整保留。
这些检查不代表视觉闭环已成功。
