# 90° 扫转没有做成

对应 `c1db667`。没有改镜头、没有训练、没有把诊断图写入训练集，也没有用 05/06/07。三次都是重新启动后的原生出生点，没有传送，也没有按记录朝向对齐。`spawn_turtlebot3.launch.py` 只传 x、y 和 z=0.01，不传 yaw。因此 `gz model` 看到的机体 yaw 都接近 0，不是各条路线记录里的起始 yaw。

## house_run_00

出生点约 (0, 0)。`align_spin_once.py` 在发速度前退出：扫描最近距离 0.120 m。没有转动。日志是 `house_run_00_left/spin.log`。采集进程当时已经在记静止图像，那些 PNG 留在本机，没有推送。

## house_run_01

`gz model -m burger_cam -p`：实体 271，位置约 (2.450, 2.745, 0.010)。记录 yaw 约 1.77 rad，实际模型 yaw 约 0。一次激光有 283 个有效点，最近 0.121 m，中位数 0.786 m，47 个点小于 0.2 m，66 个点不大于 0.3 m。没有发速度，也没有再采 18 秒窗口。

## house_run_02

实体仍是 271，位置约 (0.007, 3.837, 0.010)，模型 yaw 约 -0.009 rad。激光最近 1.337 m，没有不大于 0.3 m 的点。图像和 `/odom` 各只有一个发布者，`/cmd_vel` 发速度前没有其他发布者，订阅者是 `ros_gz_bridge`。

采集就绪后按 +0.12 rad/s、目标 90° 运行。`spin.log`：仿真运动 13.590 s，结束时模型 yaw 增量 0.000°，退出原因是 `target angle not reached`。启动终端里桥接打印过一次 `TwistStamped` 到 `gz.msgs.Twist`。

`geometry.json` 最后一帧相对首帧：模型 yaw -0.001°，odom yaw +0.054°。直接图像估计约 +0.005°，连续累计约 +0.006°。18.0 s 仿真时间里没有发生约 10°、20°、40°、60° 或 85° 的转动。137/138 张图能对齐，这只说明车几乎没动时两条姿态流是对齐的。

因此没有在原地重发，也没有改 0.3 m 条件或目标角度。90° 的左右两次扫转都还没有可分析的转动数据。
